# Chat asset references

Verified on 2026-09-07 with Twitch channel `lirik` (broadcaster ID `23161357`).

- `FlowChatAssets.graphql` was verified against https://gql.twitch.tv/gql with the app's public client ID. Root `badges` supplies global badges; `user.broadcastBadges` overrides channel badges. Both return human-readable `title` metadata. `emoteSet(id: "0")`, subscription products, and local emote sets supply Twitch emote names. Receiving messages still uses Twitch's tagged emote positions, which distinguish actual emotes from plain text.
- `FlowChatters.graphql` returns the total count and broadcaster, moderator, VIP, staff, and viewer groups. Twitch returned a maximum of 100 viewers in the sampled large channel; `viewers` accepts no `limit` argument.
- [7TV API implementation](https://github.com/SevenTV/SevenTV/blob/main/apps/api/src/http/v3/rest/emote_sets.rs): `https://7tv.io/v3/emote-sets/global` and `https://7tv.io/v3/users/twitch/{broadcasterId}`. Channel aliases are on the outer emote entry. Author names are already present at `data.owner.display_name` (fallback `username`), so no extra author request is needed. Use the returned host and `2x.webp` file; current hosts include `cdn.7tv.app`. Zero-width entries carry outer flag `1` or data flag `256`.
- [BetterTTV API](https://betterttv.com/developers/api): `https://api.betterttv.net/3/cached/emotes/global` and `/cached/users/twitch/{broadcasterId}`. Merge `channelEmotes` and `sharedEmotes`; `modifier` marks overlays. Images use `https://cdn.betterttv.net/emote/{id}/2x`.
- [FrankerFaceZ API](https://www.frankerfacez.com/developers): `https://api.frankerfacez.com/v1/set/global` and `/v1/room/{login}`. Only `default_sets` apply to everyone globally. Prefer animated image URLs when present; normalize protocol-relative image URLs to HTTPS.
- FFZ `/v1/badges` and BTTV `/3/cached/badges` provide bulk username badge assignments. Cache these for thirty minutes. FFZ includes raster URLs and background colors; BTTV provides SVG URLs, rendered with `flutter_svg`.
- 7TV sender badges use `https://7tv.io/v4/gql`: `users.userByConnection(platform: TWITCH, platformId: $id).style.activeBadge`. Live and replay messages supply numeric Twitch user IDs. Batch at most thirty lookups per request, cache badge and empty results for thirty minutes, and prefer WebP at scale 2. This matches the [current schema](https://github.com/SevenTV/SevenTV/blob/main/apps/website/schema.graphql) and [thirty-operation batch limit](https://github.com/SevenTV/SevenTV/blob/main/apps/api/src/http/v4/gql/mod.rs). The public query returned an Admin badge for user `166427338` and no badge for `23161357`.

Provider requests carry no Twitch credentials. Missing channel registrations (404) are empty sets. Successful parsed assets are cached for ten minutes with bounded channel entries; explicit refresh bypasses the cache.

Replies, moderation, and pins were verified on 2026-09-08:

- The [IRC reference](https://dev.twitch.tv/docs/chat/irc/) documents direct-parent identity/text and thread-root tags, and sending `reply-parent-msg-id`. `CLEARCHAT` identifies a banned user by `target-user-id`; `ban-duration` distinguishes a timeout and supplies seconds. `CLEARMSG` identifies one deleted message. These events update retained messages; a standalone notice remains visible when the affected message is outside the feed.
- `FlowChatReplies` resolves a selected reply's `threadParentMessage.id` (or follows `parentMessage.id` when root metadata is absent), then reads the original message and its `replies.nodes`, using the current [Twitch thread component](https://assets.twitch.tv/assets/sites.mweb.pages.channel-live.native.components.chat.components.thread-content-d5ec72df937aef5b954b.js). Loading the root includes sibling replies that are absent from the connected session's messages; server history is merged with that local history.
- The deployed thread component renders the root's replies as a flat list, including nested-parent context. Live schema checks reject `replies(first:, after:)` and `replies.pageInfo`; there is no pagination interface on this connection. Flow displays all history Twitch returns plus the connected session's history; Twitch's retention of older messages is outside Flow's control.
- Twitch's current [Hermes client](https://assets.twitch.tv/assets/21956-f5c4db98835355d9e43d.js) connects to `wss://hermes.twitch.tv/v1`. After `welcome`, a `subscribe` frame requests the public topic `pinned-chat-updates-v1.<channelID>`. Anonymous subscriptions were accepted by the live service. Notifications contain JSON in `notification.pubsub`; the [pin handler](https://assets.twitch.tv/assets/53884-7434f09ace2b442770d7.js) handles `pin-message`, `unpin-message`, and `update-message`. Only `MOD` pins are shown. Expiry is `message.ends_at`; a null expiry remains pinned until Twitch removes it.
- `FlowPinnedChat` obtains initial state from `channel(id).pinnedChatMessages(first: 1, messageType: MOD)`. Subscribe first, then load initial state and merge concurrent changes. Reconnect opens a fresh subscription and reloads current state. A real anonymous Dart connection loaded loltyler1's existing pin, then loaded it again after reconnecting. Deterministic socket tests cover removal, extension, expiry, lost keepalives, late responses, and disposal.
- Pin metadata preserves `pinnedBy` from GraphQL and `pinned_by` from Hermes separately from the message sender. On 2026-09-08, loltyler1's pin was authored by `loltyler1` and pinned by moderator `Dox_Ret`. The pin header uses that pinner's identity and moderator/broadcaster role; the body retains the author's identity and badges. Missing pinner metadata stays unknown.
- Pin snapshots use `Message.senderChatColor` and `Message.senderBadges`, matching replies. The live Clix pin returned Nightbot's moderator, 72-month subscriber, and bot badges, while `User.displayBadges` returned only a global partner badge; using the user field loses channel badges. That pin's `pinnedBy` was moderator `Bolivong`.
- The [official Helix pin endpoint](https://dev.twitch.tv/docs/api/reference/#get-pinned-chat-message) likewise distinguishes `sender_user_*` from `pinned_by_user_*`. It requires moderator permission and scopes, so the ordinary viewer path uses the same public GraphQL/Hermes mechanisms as Twitch's website. These website interfaces are not a documented third-party API contract.
